Project Overview

A two-part hardware-software co-design lab demonstrating embedded processor integration and FPGA hardware acceleration. Part 1 built a MicroBlaze SoC controlling an RGB LED via AXI GPIO and UART. Part 2 added a custom 16-bit dot product hardware accelerator that achieved a 160× speedup over the embedded CPU for n=4096 vector length.

Part 1

MicroBlaze RGB LED Controller

Built a block design in Vivado with MicroBlaze processor, AXI GPIO for LED control, and AXI UARTlite for serial communication. Deployed C firmware in Vitis that cycles the RGB LED through colors using memory-mapped Xil_Out32 writes to the AXI GPIO base address.

Part 2

Dot Product Hardware Accelerator

Custom hw_accel_dot_product.sv module integrated via AXI-Stream FIFO and DMA. Reads vector data from RAM through DMA, extracts paired 16-bit components from 32-bit AXI-Stream words, accumulates products, and outputs the result through an AXI Lite register interface.

Dot Product Architecture

The accelerator receives a 32-bit AXI-Stream input where the lower 16 bits carry vector component an and the upper 16 bits carry bn. On each valid cycle, it computes an × bn and accumulates into a running 32-bit sum. The result is exposed through an AXI Lite register that the MicroBlaze reads after the DMA transfer completes.

The data path: RAM → DMA → AXIS FIFO → Dot Product Calculator → AXI Lite → MicroBlaze. A hardware timer counts clock cycles elapsed for both the CPU and FPGA implementations, enabling a direct performance comparison.

Key Concepts

Memory-Mapped I/O: Hardware peripherals are assigned specific memory addresses, allowing the MicroBlaze processor to interact with them using standard read/write operations — the same mechanism a CPU uses for RAM, but targeting custom hardware registers.

AXI Bus Protocol: The system uses AXI for control/status (AXI Lite), high-bandwidth data streaming (AXI-Stream via DMA), and GPIO (AXI GPIO). AXI's ready/valid handshake prevents data loss between modules operating at slightly different rates.

Hardware vs Software: The software approach in Vitis allowed rapid iteration and easy debugging, while the FPGA hardware accelerator achieved dramatically lower execution time through dedicated parallel logic — demonstrating that the optimal solution often combines both.

The dot product accelerator achieved a verified 160× speedup over the embedded CPU at n=4096, with identical results confirming functional correctness.

Speedup scales with vector size — overhead dominates at small n, while FPGA parallelism dominates at large n — consistent with hardware acceleration theory.
